# V40 contract compatibility audit, 10 September 2026

This is a read-only semantic review of the 48 `packages/contracts` paths changed from declared baseline `a87f691bd` to fixed target `09e8de9c6`, compared against integrator `33065a21a`. It does not establish full V40 compatibility. It compares schema fields, literals, defaults, RPC registration, and source commits, not just filenames. No live server, installer, provider, or browser was exercised.

The completion ledger and prior correctness/protocol ledgers were read. Their broad pending groups remain pending; the findings below refine them into actionable contract gaps. Subsequent ready work is accounted for separately: nightly contract `3598fdcf2`, desktop `30e483738`, web `6c74a5bdd`; setup/import agent `31227320a` covers welcome bootstrap fields and provider-aware terminal inputs/errors. Do not reimplement those as new findings.

## Setup, provider and optional settings scope

`providerSetup.ts`, setup RPCs and `ServerProvider.setup` belong to the ongoing setup/import work (`09aac7156`). Agent-session git grouping fields (`8b2838e0e`, `62fbbe08a`) are also assigned there. `supportsConversationRollback` and `supportsTextGeneration` originate in Antigravity `06336460c`; Antigravity registration/settings are absent at this checkpoint. Preserve OMP when adding that provider.

The reset-credit success/input contracts otherwise match target. Pulse uses `ProviderResetCreditError` where target uses `ProviderSetupError`. This is a real cross-version error-union difference: add compatibility when integrating setup while retaining existing Pulse errors; do not silently remove the old tag.

Other missing client settings are additive feature work: appearance contrast (`6e9c57f7b`), panel animation duration (`91c8d4771`), recording frame rate (`395811105`), link target (`18062da94`), unpin confirmation (`22c311dde`), diff layout (`9409dd20a`), context meter (`a19f01fc1`), composer scroll collapse (`03728361a`, finalized `a12589dc0`), proactive panels (`fb93902ee`), and skill-menu choice (`9da0fab08`). Unknown fields generally disappear under the older schema; their presence is not itself a strict decode failure. Defaults and UI persistence still need coordinated implementation.

Preview also lacks `screenshotFailed` (`19c97ea56`), tab-aware automation status (`12e8997e5`), recording capture IPC changes (`ef7014d85`), SSH host resolution (`b5f4e8137`) and desktop favicon picker (`44e4a7071`). These require implementation review rather than adding declarations alone.

## Intentional differences and false positives

- Preserve Pulse Office/mail, Issues, Integrations, schedules, OMP, busy-turn behavior, updater rollback, release identity and relay clients. Their removal in a target-versus-Pulse diff is not a compatibility fix.
- Pulse raw `rateLimits` plus optional normalized `limits` intentionally support existing usage. Target uses required `limits` alone. A raw-only envelope is not target-runtime-compatible; retain both and ensure normalized-capable adapters populate limits. Do not delete Pulse data merely to match the target schema.
- Pulse optional internal auto-settle timestamp accepts a superset of target inputs. This does not prove wrong settlement; review the decider's timestamp handling separately. PR terminal timestamps use stricter ISO validation in Pulse versus target strings; upstream-generated normal ISO values remain compatible, but malformed/legacy strings deserve a targeted test before relaxing validation.
- `ModelSelection` moved between files upstream; Pulse already has its legacy provider-to-instance transform. This is not missing model selection compatibility.
- `environmentHttp.ts` differences are export visibility only. RPC/export cleanup `2ae3b712b`, `50bc62a83`, `5716dec97`, `dfc70a329` does not change wire methods where payloads match. Preserve exports consumed by Pulse.
- Thread feedback upload `3db38b881` remains a separate explicit data-flow decision from the ledger. No automatic analytics or feedback transmission is justified by contract parity.

## Path coverage and limits

All changed production contract paths were inspected through baseline history and the target-versus-integrator diff: agent sessions, assets, citations, auth/base schemas, browser import/profile, app activation, editor/environment/HTTP, Git, index/IPC/keybindings/model, orchestration/preview/project/provider/runtime/setup/usage limits, pull requests/relay/resource telemetry/RPC/server/settings/source control/terminal/usage/source IDs. Companion tests were used to establish intended defaults where relevant; their file count is not test execution evidence. `package.json` release identity stays Pulse-owned. Resource telemetry and usage-limit source IDs have no remaining semantic difference at the audited checkpoint.

No runtime checks were run for this report. Existing successful integration tests do not establish the missing groups above. The next useful batch is the quit-mode decoder plus shell/UI behavior, followed by small strict-decoder compatibility fixes; larger PR, usage, browser and theme groups need separate implementation and cross-surface verification.
