Version and capability skew

Capability is additive, never assumed

Unsupported environments stay usable and visible; the integration atom simply does not mount.

Client / server Expected behavior Verification

New client / new server The additive capability enables seven typed methods. Responses contain redacted lifecycle/context data, previews, and receipts only. Contracts, authorization, server-environment, and client-runtime suites

Compatibility rule: new clients query integrations only after the server advertises the capability.

Connection path ownership

Every route resolves to one environment

The same EnvironmentRegistry and EnvironmentSupervisor own integration routing as every other environment RPC.

Local

Primary

Reaches its own server session and preserves the primary environment ID.

Remote

Direct bearer

Persists a bearer target, authorizes against the expected environment, and returns that same ID.

Relay

Managed tunnel

Relay bootstrap and DPoP authorization are scoped to the requested environment.

SSH

Tunnel target

Opens the gateway before remote authorization and retains the tunnel target ID.

The integration atom keys reads and serialized writes by environment ID. The authenticated server session then constructs the adapter around that server’s native Issues service, preventing silent fall-through to another environment.

Persisted resource and package identities

History does not get rewritten

The adapter projects native records through the integration seam without changing identifiers.

  • Native IssueId, ThreadId, project mappings, and Issue/thread links remain in existing tables and contracts.
  • Disconnect removes the current endpoint and mappings while preserving historical Issue/thread links.
  • Native issues.* RPCs remain compatibility aliases beside additive integrations.* methods.
  • Existing package scopes, the t3 CLI/package identity, Expo project identity, and persisted T3 configuration aliases stay stable.
  • Mobile receives connection health, mappings, provenance, and capability state—but never provider token, refresh token, client secret, or authorization value.
