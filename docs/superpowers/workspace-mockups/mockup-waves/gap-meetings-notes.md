### How notes reach agents

Verified: `workspace_read_item` first calls `resolveLinked` and refuses items not linked to the calling thread or its project, at `apps/server/src/mcp/toolkits/workspace/handlers.ts:71`. `WorkspaceLinks.contextFor` and `resolveLinked` consider those direct owner keys, at `apps/server/src/workspace/WorkspaceLinks.ts:244`. Project hub one-hop related rows explicitly do not become agent context, at `apps/server/src/workspace/WorkspaceLinks.ts:277`.

Therefore the proposed implementation must not assume `project -> meeting -> note` authorizes a note read. Use explicit direct note-to-project links when notes are created for that project. Start thread from a meeting should present the meeting and its confirmed note links as context chips; the existing action path can carry these endpoints. Start thread from a note carries the note itself. Keep confirmation tied to the submitted message. If a note is merely shown as related, require an explicit Add to context action before granting the agent access. Unlinking one owner removes that grant, but a surviving direct link to the thread or its project still authorizes access.

Proposed MCP dispatch adds `pulse-meeting`, `pulse-note`, and optionally published `pulse-talk` branches to the existing resource case. A meeting read returns bounded metadata, agenda references and safe item keys, not recording bytes or an attendee's unrelated documents. A note read returns plain text with revision and bounded continuation offsets, source attribution and availability. Do not automatically follow meeting-note references on behalf of the agent. Offset validation must reject negatives, unsafe integers, and split UTF-8 boundaries; an edited note invalidates old continuation state explicitly. Use the current result byte limit, and treat every note, comment and transcript as untrusted content.

Verified: existing Drive note reads can already use `workspace_read_item`'s file branch, at `apps/server/src/mcp/toolkits/workspace/handlers.ts:118`. `DriveService.readFile` requires a user-selected binding, rechecks connection generation, validates offsets, and bounds text at `apps/server/src/drive/DriveService.ts:88`. Google Docs exports to plain text in `apps/server/src/drive/DriveApi.ts:147`; that read is not a formatted Docs renderer or comments feed.

Verified: linked-item context is capped at 30 items and 4096 bytes at `apps/server/src/workspace/linkedItemsContext.ts:13`, and titles/content are explicitly data at `apps/server/src/workspace/linkedItemsContext.ts:20`. The provider text is assembled centrally at `apps/server/src/orchestration-v2/ProviderTurnStartService.ts:1051`. Proposed behavior keeps that path shared across providers. A provider without usable workspace MCP can see the bounded link manifest but must not be advertised as able to retrieve the full note. Verify MCP capability on each configured provider rather than adding meeting-specific adapter logic.

### Remote-ready and phone contract

Proposed: store meeting summaries, notes, links, revisions and published transcripts in the chosen server environment. Use authenticated existing-origin RPC/HTTP routes through local, Tailscale and relay/tunnel connections. Do not bake origins into the UI, send desktop paths to browsers, or use desktop IPC as a remote API. Calendar OAuth, refresh credentials and connection health belong on the server for this workflow. Existing desktop accounts need explicit reconnection or a deliberately reviewed migration; never silently copy credentials from local encrypted Office storage.

Proposed: at phone width show one pane at a time: day list, meeting, then Notes/Context. Keep join and notes actions reachable without right-click. Restore date and selected item on Back, allow text selection, use touch targets around 44px, and retain notes during a lost connection with a visible stale/read-only state. Never silently queue invitations or recordings while disconnected. Native React Native screens remain a separate scope decision; responsive web is the default phone delivery under the current spec.

Proposed: local capture stays on the device with the microphone/system-audio permission. A remote Join action opens the phone's call, not the host computer's call. A remote browser or agent cannot start a host microphone under a link-read grant. A published transcript may be readable remotely after explicit sharing; capture consent and agent access are separate choices. These rules also apply when the desktop client is connected to a server on another machine.
