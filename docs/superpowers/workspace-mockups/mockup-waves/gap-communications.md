### Message stream, replies and outbound actions

**V.** Telegram landed in `apps/server/src/telegram/`, not `packages/workspace-telegram`. Commit `cb6caf3748` adds TelegramBotApi, TelegramService, TelegramStore and migration 060 and removes TelegramAdapter plus its dependency. See `apps/server/src/telegram/TelegramService.ts:41`, `apps/server/src/telegram/TelegramStore.ts:101`, `apps/server/src/persistence/Migrations/060_TelegramReader.ts:1`.

**V.** Telegram connects with getMe, requires a bot identity, rejects an active webhook, saves the token in server secrets and starts a scoped worker. It long-polls message, edited_message and membership updates; it commits the complete batch and next offset before acknowledging it in the next request. See `apps/server/src/telegram/TelegramService.ts:61`, `apps/server/src/telegram/TelegramService.ts:112`. Pairing codes expire after ten minutes; received text is stored only for paired private/group/supergroup chats. `/unpair` from the pairing user and bot removal deactivate a chat. See `apps/server/src/telegram/TelegramStore.ts:148`, `apps/server/src/telegram/TelegramStore.ts:189`. This is received bot-visible data, not personal-account synchronization or old-history import.

**V.** The Telegram RPC family is listConnections, connect, disconnect, start/cancelPairing, listChats, removeChat, listMessages, readMessage and subscribeChanges. The low-level `sendMessage` exists, but its service caller sends pairing notices only, `apps/server/src/telegram/TelegramService.ts:80`.
