## 1. Screens covered

This report covers docs/superpowers/workspace-mockups/mockups/03-tasks.png, docs/superpowers/workspace-mockups/mockups/08-calendar-tasks.png, and the Tasks resource tab. ### Proposed task behavior and data

1. Completion has one source of truth: keep the existing column and add nullable completedColumn to project config. It must name one configured column. Migrate the exact existing Done default; custom configurations without Done stay unset until a completed column is explicitly designated. Do not infer completion from translated strings or last-column position. The server returns derived done state. Check moves to completedColumn; uncheck reopens into the first configured non-completed column. Require at least one open column. Board movement uses that same rule. Config changes that reinterpret existing completions require explicit confirmation with affected counts. No independent checkbox boolean that can disagree with Board.
2. Add nullable dueOn as a real validated Gregorian YYYY-MM-DD. Never store it as UTC midnight. Detail sets/clears it. Render Today in the selected display timezone, otherwise d MMM, adding year when needed; expose full date and overdue meaning accessibly. Null has no invented date. Store one environment workspace timezone preference, defaulted from host at setup and editable; show IANA zone in Calendar. Remote devices using the same zone agree on Today; dueOn never shifts. Timed reminders are separate scope.
3. Assignees default to environment-owner, displayed Me, for new tasks; allow Unassigned. This is the human accountable within this local-first environment, not the current browser/device, OAuth account, Git author or agent. All paired clients see the same owner. Use an existing suitable environment display profile or add a small name/initials preference, fallback ME. Legacy tasks start Unassigned to avoid invented attribution. MC/LM/NP/AM are fixture data only. More people require an identity/access decision; do not create a directory to fill sample circles.
4. Add optional bounded areaLabel text, such as Marketing or Website, unless another approved wave establishes a reusable field first. Project title comes from actual projectId. Area is task metadata, not a Drive folder, separate project or permission.
5. Global list means all active projects in one selected environment, optionally filtered to a project. All tasks/Open/Done controls status. The screenshot combines status=all with project=SynKEK, hence Project tasks and 4 open. Unfiltered global mode says All tasks and reports environment-wide counts. A union across environments is later scope, not an automatic request to every server.
6. Add a capability-gated paged summary RPC with projectId?, status, bounded text search, due and owner filters, cursor and page size. Return project title, derived done, due, owner, area, exact filtered counts and next cursor. Keep old listTasks for compatibility. Filter/sort in SQL; no N-project client fanout over truncated 200-row lists. Default order is open before done, dated before undated, date ascending, ID tie-break. Bind cursor to filters/order. Exclude deleted projects in global results, but retain unavailable direct links.
7. Board is another rendering of the same scope/filters. For one project, lanes follow existing taskColumns order, include empty lanes and counts, and contain title/metadata/date/owner cards with completion and Move to column menu. Suggested card styling: quiet 1 px border, 8 px radius, 12 px padding. Keyboard/touch menu works before optional drag. No rank field, WIP limits, dependencies or recurrence. Sort cards using list order. All-project Board groups by project with its own lanes, preserving custom vocabulary. A single universal lane taxonomy needs a maintainer decision. This layout is proposed because no board screenshot exists.
8. Search matches title/area. Filter popup offers due Any/Today/Overdue/No date and owner Me/Unassigned, Clear filters and active count. Project selection is explicit. Filters/status/date belong in URL for reload/Back; view preference may remain per device. Query changes reset pagination, never mutate task data.
9. Title opens task detail with title/column/due/owner/area editing and the canonical ref. Right context shows actual links and separately labelled owning project. Reuse WorkspaceItemMenu and Start thread/project/automation. One task across list/board/panel/calendar remains one ref. Checkbox writes must not navigate or start agents. Soft-deleted tasks retain links with a reason when opened.
10. Tasks resource tab scopes to the project in its header. Resolve structural project for selected tasks; otherwise use explicitly linked projects or independent resource selection. Multiple projects require a picker. No project says Choose a project to see its tasks. Show all statuses, exact open count and a compact shared row component. Same service/atoms as center. Task details may open in a sheet so Calendar remains behind them. Switching tabs must preserve day/module.

Use a narrow metadata patch with expected revision and explicit desired completion/move state. Preserve older upsert compatibility: an old title edit must not clear newer metadata. Conflicts refresh the row and offer retry; retrying complete(true) is idempotent, unlike a blind toggle. Use existing Intl/date helpers before adding dependencies.

### Proposed server-owned calendar

Build WorkspaceCalendar under apps/server, persisted in the environment database, with typed thin RPCs, read/operate scopes, capability flags, environment change stream and client-runtime atoms. Desktop renders the same service through shared web. Remote and phone browsers use the selected server, never Electron IPC or the desktop accounts file. Follow the existing WorkspaceTools service model, without a new workflow engine.

Separate task-due agenda rows from event rows. Due rows reference existing tasks and dueOn, with no duplicate event record. Event rows have stable server IDs, title, optional description, either date-only all-day start/end-exclusive or UTC start/end with IANA zone, optional validated HTTPS meetingUrl, source label, optional attendee display data, revision and cancellation/deletion state. Provider-backed events, if approved, add account/calendar/provider-event/occurrence identity without tokens in responses. Events use explicit project links, not another project calendar slot.

Range query takes display zone, half-open range, optional project/calendar scope, cursor/page size. Return bounded summaries, range coverage, source availability and change revision. Load descriptions/notes on selection. Use overlap semantics for cross-midnight/multi-day events. All-day end is exclusive; due tasks sit in an untimed section. Test DST gaps/folds and remote timezone changes. Attendee names/descriptions remain untrusted data.
